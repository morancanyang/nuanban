# 桌宠原生公共图标定位

> 文档同步：2026-10-22。产品显示名称为**微光指引**；[当前功能与平台边界](product-current-state.md)统一说明现行入口、已实现范围和待验证能力。本文已有测试数字与生成日期仍只对应原批次，不因文档更新自动视为重新验收。

## 后续入口与验证边界（2026-10-22）

原生公共图标/UIA 识别与[单帧图片定位](single-frame-guidance.md)是不同路径；前者只能使用当前授权来源实际发现的公共控件，后者要求本人预览并确认待发送图像，之后仍须本地复核。不能把“文字说请双击微信”当成位置已绘制，也不能为补箭头编造微信坐标。真实桌面局部实测及空档限制见[2026-10-21 记录](cursor-guidance-fullpath-2026-10-21.md)；该记录不代表当前设备连续微信教学已通过。

## 2026-10-20 修复范围

- 本机中文 Windows OCR 和人脸检测可用，但任务栏微信通常只有图标；仅识别文字的链路无法把它纳入模型的可选目标。
- Windows 本地检测器增加只读 UI Automation 公共入口补充。该入口早已不限于写死白名单：任何 explorer 拥有的桌面/任务栏 shell 元素，其本机 UIA Name 清洗后都成为候选（见下方 2026-10-24 条目）；不遍历聊天正文或业务软件控件，不返回任务栏完整名称或任意窗口标题，不操作鼠标键盘。
- 仅本次授权来源实际采集的帧可请求公共图标检测；附件、伪造帧、历史帧、停止后的帧和范围外图标均不能借用屏幕权限。
- 仅接受 Windows Explorer 拥有的桌面/任务栏入口，结合控件可见性与屏幕命中测试排除离屏、被遮挡和范围外目标。位置来自本次本地检测时的系统可访问性控件，不是 OCR 猜测、截图模板或仅凭进程存在生成的坐标；仅用于独立公共控件布局。
- UI Automation 检测在临时每显示器 DPI 上下文中运行，并在退出时恢复；物理像素坐标先转换为本帧坐标，再由原有屏幕几何换算为 Electron DIP 箭头位置，兼容裁剪、负坐标显示器与缩放，避免 150% 缩放下混用单位。
- 带原生图标的云分析仅发送独立公共控件布局；不发送原始桌面、完整系统可访问性名称或 UI Automation 标识。OCR、人脸检查、敏感画面保护及五秒帧有效期均保留。
- 控件布局模式的上下文只依赖实际发送的公共控件，避免无关正文/OCR 抖动反复取消同一分析；每帧仍完整检查隐私。控件、范围或显示器变化仍使旧箭头失效。
- 模型回复恰逢两次捕获之间且本地帧已过期时，立即在同一授权范围补采一次新画面并核验；不重复上传，不修改旧帧时间，不使用过期坐标。
- 人脸检测与 OCR 并行启动，但必须都完整结束后才进入门控；失败时取消未完成的人脸检测并等待退出。

## 2026-10-24 候选泛化：任何 UIA 可读 shell 项都可被指引（`deviceVerified=false`）

现场问题：整屏共享时桌面第二列顶部的 WeGame 图标（黑底橙色）提示“尚未识别为可指引控件”，没有箭头。根因是 `apps/desktop/observation/windows-shell-controls.ps1` 只给写死白名单打标签，其余名称直接 `continue`。修复后：

- 枚举到的**每个合格 shell 元素**都作为候选上报，`label` 取该元素本机 UIA `Name`（本地读取，不联网）；已知项继续映射友好名（微信/开始/搜索/此电脑/回收站/控制面板）。
- 名称清洗：Trim、去控制字符、折叠空白、NFKC 归一、长度上限 64（超长按上限截断，异常超长回包直接拒绝）、桌面项去 `.lnk`；空名/纯空白/纯符号跳过；同名同位置重复项去重。
- 既有边界全部保留：仅 explorer 拥有的 shell 窗口、DPI、`IsOffscreen`/`IsEnabled`、矩形有效且完全落在观察范围内、屏幕命中测试、窗口 ≤128 / 元素 ≤1024 / 控件 ≤128。
- 门控不放宽：候选仍是本地信息，仍要经同一采集作用域、同帧、5 秒 maxAge、generation 与模型输出校验；shell 名称同样过敏感文本门控（命中即不上报，也不会停止已授权共享）；不新增自动点击或输入，不外发原始屏幕。
- **OCR 兜底未实现**：UIA 名为空/纯符号的元素仍被跳过，没有用本地 OCR 就近匹配；无名图标的图形候选仍由既有 `visual-controls.cjs`（“未标注图标” + 外观指纹）在本人框选/已授权共享路径提供。
- 验证：新增/更新合成单测覆盖任意名称（WeGame、中文名、超长、空名、控制字符、纯符号）、友好名映射、同名同位置去重、数量与范围过滤，以及运行时对非白名单桌面入口的箭头续显；`pnpm typecheck` 通过。**真机验收未完成**：需要用户在整屏共享下点击“重新识别当前画面”后确认 WeGame 出现箭头，并核对箭头位置与图标一致。

## 2026-10-24 周期抽帧 tick 合并而非取消：核验不再卡在“正在分析画面”（`deviceVerified=false`）

现场问题：第一步截帧与箭头正常，用户点“我点好了，请核验”后一直显示“正在分析画面”，最后报“本次分析未获得可核验的结果”。`%APPDATA%\@nuanban\desktop\guidance-trace.log` 每约 3 秒稳定重复 `capture_cycle(allow) → analysis_error(ANALYSIS_CANCELLED, timedOut:false) → analysis_request(page_changed, ~1.6MB) → analysis_image_scaled(0.77MB, 1600×1000)`，即周期 `page_changed` tick 取消并立刻重发仍在飞行中的请求；一次桌面提供方分析实测 >3.5 秒 > 3 秒 tick，请求永远拿不到结果（活锁）。修正后：

- 飞行中的分析不再被周期 tick 取消：tick 合并/延后（`analysis_deferred{reason:'in_flight'}`），本人动作（结束观察、改范围、停止共享、重新提问、点核验）与“预期控件已出现”的自动续步仍立即取消并重发（`analysis_preempted`）。取消权仍只属于本人动作。
- 合并后的补发遵守**最小间隔 6 秒**与**连续慢响应退避**（6→12→24 秒上限，`analysis_recheck_scheduled{delayMs,trigger,slowStreak}`）；退避只延后补发，不放宽五秒帧龄、准入、来源/几何与敏感文本门控。只有这次分析根本没发出去（`analysis_skipped`）才自动补发一次。
- 核验路径跑到完成或明确失败，失败透出真实原因（`target_not_in_current_frame`、`completion_not_verified`、`previous_step_not_verified`、`stale_analysis_frame`、`invalid_analysis*`、非本人取消的 `ANALYSIS_CANCELLED`），兜底文案只作最后手段；采集范围变化或新画面无可核验控件时明确作废（`analysis_abandoned`）而不是静默停在“正在分析画面”。
- 真机验收未完成（`deviceVerified=false`）：需要用户在整屏共享下点“我点好了，请核验”，确认不再卡住并拿到箭头或真实失败原因；本轮只有假时钟 + 假 provider 的合成单测（`tests/platform/desktop-guidance-analysis-recheck.test.ts`）与 trace 事件写入断言。

## 验证与边界

定向单测覆盖授权来源、坐标映射、名称清洗（不再限于白名单）、未请求结果拒绝、附件隔离、脱敏布局、敏感内容以及回复/捕获间隙。真实 Windows 检测使用内存画面，只输出固定计数、耗时和原因，不落盘私有画面或 OCR 正文。

- 六个相关单测文件：600 项通过；`pnpm typecheck` 通过。
- `node scripts/test-desktop-wechat-guidance.mjs`：真实 Windows OCR、合成模型、真实 Electron 指引窗口与绘制像素检查通过，不读取真实桌面或调用真实云模型。
- `node scripts/test-desktop-observation-continuity.mjs`：四项通过，三帧持续观察及敏感合成帧暂停均符合预期，真实桌面捕获和云调用均为零。
- 本机真实采集链路的只读诊断：2560×1600、150% 缩放下，OCR 未识别到“微信”文字，但系统公共控件检测识别到微信任务栏入口；通过原有安全及时效检查的帧包含一个微信目标。私有画面未上传、未写入报告或提交。
- 已配置模型追加验证：使用合成公共控件画面调用本机现有加密配置的真实模型一次；模型返回合法目标，等待新本地帧复核后，真实 Electron 箭头窗口完成绘制。共采集三次合成画面，未上传真实桌面或输出凭证。默认回归脚本仍不调用真实供应服务。

上述测试不等于真实用户桌面的持续操作、全部供应服务或正式发布验收均已完成。目标缺失、被遮挡、画面过期、授权停止或敏感画面时不得伪造箭头；后续仍由用户亲手点击。
